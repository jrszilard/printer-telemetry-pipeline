# Log formats

The fleet simulator writes three printer generations in deliberately different formats, and the
collector stores real PrusaLink readings as a fourth source. The parser (`telemetry/sql/parse.sql`) picks
a branch from the `source=` folder a file lands in, then maps every format into one schema.

Every example below is **synthetic**, generated by `telemetry.simulate_fleet` (seed 42). The formats are
invented to exercise the pipeline and do not describe any manufacturer's real logs. They are written by
`format_event` in `telemetry/simulate_fleet.py` and land under
`data/<name>/landing/received_date=…/source=…/`, which Git ignores.

| Source | Firmware | Format | Event time | What makes it awkward |
|---|---|---|---|---|
| `genA` | 1.4.2, 1.5.0 | Plain text, one upload header per file | Device clock with no timezone, estimated from the header | Unreliable clocks; a cut-off line can still parse |
| `genB` | 2.0.3, 2.2.0 | JSON with short keys | Milliseconds since 1970, UTC | Temperature fields renamed by firmware; some printers report °F |
| `genC` | 3.0.1, 3.1.0 | Nested JSON | ISO 8601 with a timezone offset | Firmware 3.1.0 adds an event that parser v1 rejects |
| `prusalink` | Real printer | Collector record wrapping two API responses | Receipt time only | No start or end events, so no outcomes |

## Generation A: plain text

```text
#UPLOAD device=sim-000000 model=A fw=1.4.2 device_time=2026-09-28 08:00:00
2026-09-27 20:00:00 IDLE bed=24.1 nozzle=25.5 tgt_bed=0 tgt_nozzle=0 fan=100 job=-
2026-09-28 04:07:00 JOB start id=sim-000000-20260928-0 material="PLA" layers=144
2026-09-28 04:07:00 THERM bed=59.9 nozzle=214.9 tgt_bed=60 tgt_nozzle=215 fan=100 job=sim-000000-20260928-0
2026-09-28 06:01:00 JOB end id=sim-000000-20260928-0 result=ok
2026-09-29 06:20:00 ERR code=E_MOTION job=sim-000051-20260929-0
2026-09-29 06:22:00 JOB end id=sim-000051-20260929-0 result=fail
2026-09-28 06:04:00 JOB end id=sim-000048-20260928-0 result=unknown
2026-09-28 02:00:00 DBG subsystem=network message=heartbeat
```

- The `#UPLOAD` header is metadata, not an event. It carries the device id, model, firmware and what the
  printer's clock read at upload. Event time is estimated as
  `received_at − (header device_time − line time)` and labelled `upload_offset_estimate`. The estimate
  holds only if the clock was steady and the upload was quick.
- `THERM` and `IDLE` lines are status readings (`PRINTING` and `IDLE`). `job=-` means no job.
- `result=ok`, `fail` and `unknown` become `success`, `failure` and `unknown`.
- `DBG` lines are rejected as `unsupported_kind`.
- **Known limitation:** the simulator cuts off about 0.2% of status lines. JSON truncation is caught as
  invalid JSON, but a cut-off text line can still parse. For example,
  `2026-09-28 05:20:00 THERM bed=100.1 nozzle=25` is accepted with a nozzle temperature of 25 and no job
  id. Requiring every expected field, such as the trailing `job=`, before accepting a line would catch it.

## Generation B: JSON with short keys

```json
{"t":1790553600000,"dev":"sim-000007","model":"B","fw":"2.0.3","k":"status","temp_bed":24.3,"temp_nozzle":25.3,"target_bed":0,"target_nozzle":0,"temp_unit":"C","state":"IDLE"}
{"t":1790553600000,"dev":"sim-000001","model":"B","fw":"2.2.0","k":"status","bed_temp":24.8,"nozzle_temp":25.5,"target_bed":0,"target_nozzle":0,"temp_unit":"C","state":"IDLE"}
{"t":1790553600000,"dev":"sim-000004","model":"B","fw":"2.2.0","k":"status","bed_temp":77.0,"nozzle_temp":77.72,"target_bed":32.0,"target_nozzle":32.0,"temp_unit":"F","state":"IDLE"}
{"t":1790582940000,"dev":"sim-000001","model":"B","fw":"2.2.0","k":"job_start","job":"sim-000001-20260928-0","material":"PLA","layers":125}
{"t":1790677920000,"dev":"sim-000034","model":"B","fw":"2.0.3","k":"error","job":"sim-000034-20260929-0","code":"E_MOTION"}
{"t":1790589780000,"dev":"sim-000001","model":"B","fw":"2.2.0","k":"job_end","job":"sim-000001-20260928-0","ok":true}
{"t":1790678040000,"dev":"sim-000034","model":"B","fw":"2.0.3","k":"job_end","job":"sim-000034-20260929-0","ok":false}
{"t":1790588580000,"dev":"sim-000055","model":"B","fw":"2.2.0","k":"job_end","job":"sim-000055-20260928-0"}
{"t":1790583000000,"dev":"sim-000001","model":"B","fw":"2.2.0","k":"status","job":"sim-000001-20260928-0","bed_temp":59.8,"nozzle_temp":215.7,"target_bed":60,"target_nozzle":215,"temp_unit":"C","sta
```

- Firmware 2.0.3 writes `temp_bed` and `temp_nozzle`; 2.2.0 writes `bed_temp` and `nozzle_temp`. It is the
  same format, so one parser accepts either name.
- `temp_unit` is explicit. Fahrenheit readings are converted to Celsius in the clean layer.
- `ok: true` and `ok: false` become `success` and `failure`. A `job_end` with no `ok` becomes `unknown`.
- The last line is cut off and rejected as `invalid_json`.

## Generation C: nested JSON

```json
{"ts":"2026-09-28T02:00:00+02:00","device":{"id":"sim-000002","model":"C","fw":"3.0.1"},"type":"status","temps":{"bed_c":24.3,"nozzle_c":25.2,"chamber_c":24.0},"targets":{"bed_c":0,"nozzle_c":0},"state":"IDLE"}
{"ts":"2026-09-28T10:23:00+02:00","device":{"id":"sim-000002","model":"C","fw":"3.0.1"},"type":"job_start","job":{"id":"sim-000002-20260928-0","material":"PETG","layers":193}}
{"ts":"2026-09-28T10:23:00+02:00","device":{"id":"sim-000002","model":"C","fw":"3.0.1"},"type":"status","job":{"id":"sim-000002-20260928-0"},"temps":{"bed_c":80.6,"nozzle_c":238.6,"chamber_c":35.4},"targets":{"bed_c":80,"nozzle_c":240},"state":"PRINTING"}
{"ts":"2026-09-28T12:19:00+02:00","device":{"id":"sim-000035","model":"C","fw":"3.1.0"},"type":"error","job":{"id":"sim-000035-20260928-0"},"error":{"code":"E_FILAMENT"}}
{"ts":"2026-09-28T12:05:00+02:00","device":{"id":"sim-000002","model":"C","fw":"3.0.1"},"type":"job_end","job":{"id":"sim-000002-20260928-0"},"outcome":"success"}
{"ts":"2026-09-29T12:03:00+02:00","device":{"id":"sim-000020","model":"C","fw":"3.0.1"},"type":"job_end","job":{"id":"sim-000020-20260929-0"},"outcome":"unknown"}
{"ts":"2026-09-28T08:00:00+02:00","device":{"id":"sim-000017","model":"C","fw":"3.1.0"},"type":"maintenance","action":"filter_check"}
```

- Timestamps must carry an offset (`Z` or `±hh:mm`); without one, the line is rejected as
  `invalid_device_time`. Times are converted to UTC.
- Only generation C reports a chamber temperature.
- Firmware 3.1.0 adds `maintenance` events. Parser v1 rejects them as `unsupported_kind`; parser v2 accepts
  them after a `--reprocess` replay of the raw files.

## PrusaLink: real printer readings

The collector does not receive a log. Each poll makes two GET requests and stores one record, built in
`collect_once` in `telemetry/collect_prusa.py`. Shape, with placeholder values:

```json
{"source":"prusalink","received_at":"<UTC time the reading arrived>","request_started_at":"<UTC time the request began>",
 "timestamp_quality":"received_only",
 "device":{"id":"prusa-<hash of serial>","model":"Prusa Core One","fw":"<firmware version>"},
 "status":{"printer":{"state":"PRINTING","temp_bed":60.1,"temp_nozzle":215.0,"target_bed":60,"target_nozzle":215}},
 "job_http_status":200,"job":{"…":"job details, or null when no job is active"}}
```

- PrusaLink supplies no event time, so readings use receipt time and are labelled `received_only`.
- The serial number is hashed and credential fields are removed before storage. Job details can still
  contain private file names, so real captures stay in ignored `data/real/` and are never committed.
- Snapshots carry no start or end events, so a real print has no recorded outcome. The pipeline leaves it
  unknown rather than inferring success.

## Field mapping

How `parse.sql` reads each field from each source:

| Field | `genA` | `genB` | `genC` | `prusalink` |
|---|---|---|---|---|
| Device id | header `device=` | `dev` | `device.id` | `device.id` |
| Model | header `model=` | `model` | `device.model` | `device.model` |
| Firmware | header `fw=` | `fw` | `device.fw` | `device.fw` |
| Event kind | line label (`THERM`/`IDLE`, `JOB start`, `JOB end`, `ERR`) | `k` | `type` | always `status` |
| Event time | estimated from the upload header | `t` (milliseconds, UTC) | `ts` (must have an offset) | `received_at` |
| Job id | `id=` or `job=` | `job` | `job.id` | `job.id` |
| State | `THERM` → `PRINTING`, otherwise `IDLE` | `state` | `state` | `status.printer.state` |
| Material | `material="…"` | `material` | `job.material` | `job.material` |
| Bed temperature | `bed=` | `bed_temp` or `temp_bed` | `temps.bed_c` | `status.printer.temp_bed` |
| Nozzle temperature | `nozzle=` | `nozzle_temp` or `temp_nozzle` | `temps.nozzle_c` | `status.printer.temp_nozzle` |
| Temperature unit | Celsius | `temp_unit` (default Celsius) | Celsius | Celsius |
| Outcome | `result=ok\|fail\|unknown` | `ok` true/false, missing = unknown | `outcome` | none |
| Error code | `code=` | `code` | `error.code` | none |

## Rejected lines

Lines that fail a check go to `unparsed` with the file, line number and the first reason that applies:
`unsupported_source`, `invalid_json`, `missing_device`, `invalid_received_time`, `invalid_device_time`,
`future_event_time` (more than five minutes after receipt), `unsupported_kind`, `missing_job_id`,
`missing_temperature`, `unsupported_temperature_unit`, and `invalid_temperature` (outside −50–200 °C for
the bed or −50–500 °C for the nozzle).

Each rejected line also keeps its device and firmware, so rejects can be counted by firmware version. The
firmware comes from the line itself, the generation A upload header, or the readable lines of the same
upload, and `firmware_source` records which (`line`, `header`, `same_upload` or `unknown`). In a
60-printer, 2-day run with parser v1, every rejected line got a firmware this way, and the quality report's
`format_change_suspects` flagged exactly one: the `maintenance` events that only firmware 3.1.0 emits.
